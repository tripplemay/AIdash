## 1. 背景与目标

### 1.1 背景

AI Dash 系统当前的 AI 能力集中在课程研发模块（结构化的课程生成流水线）。教师和教学主管在日常工作中有大量非结构化的 AI 需求：

- 教师想问"这节课的导入环节可以怎么设计？"
- 教学主管想快速测试一个课程方向的可行性
- 管理员想了解 AI 对某个教学理念的理解

这些需求不适合走课程研发流水线，需要一个灵活的自由对话入口。

### 1.2 目标

在系统内新增「问 AI」模块，提供类 ChatGPT 的对话体验：

1. **通用 AI 助手**：回答任意问题
2. **课程设计专家模式**：注入课程设计基线知识，提供专业咨询
3. **对话持久化**：支持查看历史、继续对话
4. **成本可控**：独立的模型配置 + 调用日志追踪

### 1.3 设计原则

- **与现有系统一致**：嵌入 AppShell，共享 Sidebar / TopBar / 认证
- **两种模式清晰分离**：通用模式不注入额外上下文，课程设计模式注入基线
- **对话体验优先**：流式输出、Markdown 渲染、自动生成标题

## 4. 功能需求

### 4.1 对话列表（左侧，280px）

- 顶部"+ 新建对话"按钮
- 对话按最近更新排序
- 每条显示：标题 + 模式标签（通用 / 课设）+ 相对时间
- 选中对话高亮
- 右键/操作菜单：重命名、删除
- 选中后右侧加载对话内容

### 4.2 新建对话

点击"+ 新建对话"，弹出模式选择：

| 模式 | 标识 | 说明 |
|------|------|------|
| **通用模式** | `general` | 通用 AI 助手，可回答任何问题 |
| **课程设计模式** | `course_design` | AI 具备课程设计基线知识，适合课程规划咨询 |

点击即创建对话并进入。

### 4.3 对话区域（右侧）

**空状态**："选择或创建一个对话"

**消息展示**：
- 用户消息：右对齐
- AI 消息：左对齐
- AI 消息支持 Markdown 富文本渲染（标题、列表、代码块、表格等）
- 流式输出时显示打字光标动画

**输入栏**：
- 自适应高度 textarea
- Enter 发送，Shift+Enter 换行
- 发送按钮
- 流式输出期间禁用输入和发送

### 4.4 对话标题自动生成

第一轮对话（1 条用户消息 + 1 条 AI 回复）完成后：
- AI 自动生成 10 字以内的标题
- 通过 SSE 事件通知前端更新对话列表
- 不阻塞用户操作

### 4.5 对话管理

- **重命名**：用户可手动修改对话标题
- **删除**：删除对话及全部消息（需确认）
- **继续**：点击历史对话可继续发送消息

## 5. AI 模式设计

### 5.1 通用模式

System Prompt：
```
你是一个智能助手。请用中文回答用户的问题，回答要准确、清晰、有帮助。
支持使用 Markdown 格式（标题、列表、代码块、表格等）来组织回答。
```

### 5.2 课程设计模式

System Prompt：
```
你是一个智能助手，同时也是 AI 辅助教学课程设计专家。

你具备以下课程设计基线知识，请在回答课程设计相关问题时参考：

# 课程设计基线
{通用基线内容}
{分层规则矩阵}

对于非课程设计的问题，正常回答即可。
支持使用 Markdown 格式来组织回答。
```

基线内容通过 `assembleBaselines()` 获取通用基线和矩阵，与课程研发模块复用同一套基线系统。

### 5.3 模板系统集成

- 优先从 DB 加载 Prompt 模板
- DB 无模板时 fallback 到硬编码
- 管理员可在 `/admin/prompt-config` 中编辑对话模板

## 6. 多轮对话

### 6.1 上下文管理

每次发送消息时，将对话完整历史组装为消息数组发送给 AI：

```
[
  { role: "system", content: "system prompt..." },
  { role: "user", content: "第1轮用户消息" },
  { role: "assistant", content: "第1轮AI回复" },
  { role: "user", content: "第2轮用户消息" },
  ...
]
```

### 6.2 上下文长度控制

长对话可能超过模型上下文窗口，策略：
- 估算历史 token 数（中文 1 字 ≈ 2 token）
- 超过阈值时截断最早的消息，只保留最近 N 轮
- System prompt 始终保留（不截断）

## 7. 流式输出（SSE）

发送消息后，AI 回复通过 Server-Sent Events 流式返回：

| 事件类型 | 数据 | 说明 |
|---------|------|------|
| `delta` | `{ text: "..." }` | AI 输出的文本片段 |
| `title` | `{ title: "..." }` | 自动生成的对话标题（首轮对话后） |
| `done` | `{ tokens: { input, output }, cost }` | 完成，含 token 统计和费用 |
| `error` | `{ message: "..." }` | 错误信息 |

---

## 8. AI 模型配置

管理员在 `/admin/ai-settings` 中为 `chat` 动作配置独立的模型：

| 配置项 | 说明 |
|--------|------|
| actionKey | `chat` |
| actionLabel | AI 对话 |
| actionType | `text` |
| 提供商 + 模型 | 管理员自选（建议响应快、上下文长的模型） |

对话和课程生成可使用不同的模型（对话更注重速度，生成更注重质量）。

---

## 9. 费用追踪

复用 `CourseRndAiCallLog` 表：
- `projectId`: null（对话无关联项目）
- `pageKey`: `"chat"`
- `actionType`: `"chat"`
- `promptLog`: 完整 system prompt
- `messageLog`: 用户最新消息（不记录完整历史，避免数据膨胀）

管理端"AI 调用记录"页面可按 `actionType: "chat"` 筛选查看对话调用。

## 10. 数据模型

### ChatConversation（对话）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | String | 主键 |
| userId | String | 所属用户 |
| title | String | 对话标题，默认"新对话" |
| mode | String | `"general"` / `"course_design"` |
| createdAt | DateTime | 创建时间 |
| updatedAt | DateTime | 更新时间 |

### ChatMessage（消息）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | String | 主键 |
| conversationId | String | 所属对话 |
| role | String | `"user"` / `"assistant"` |
| content | String (LongText) | 消息内容 |
| createdAt | DateTime | 创建时间 |

## 12. 安全要求

| 项目 | 要求 |
|------|------|
| 数据隔离 | 用户只能访问自己的对话，API 层校验 userId 归属 |
| 输入校验 | 消息内容不能为空，长度限制 |
| 并发防护 | 前端禁用发送按钮防止重复提交 |
| 成本追踪 | 每次调用记录 token 数和费用 |
