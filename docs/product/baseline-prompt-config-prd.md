# 自定义课程生成基线与提示词模板 — 产品设计文档

> 版本：v1.0
> 状态：待确认
> 关联技术方案：`docs/tech/baseline-prompt-template-implementation-plan.md`

---

## 1. 背景与问题

### 1.1 现状

AI Dash 课程研发模块通过 AI 生成课程框架和课次教学方案。AI 生成的质量由三部分决定：

1. **课程设计基线**：一套课程设计原则与约束（如"每节课只解决一个核心问题"、"课程必须有明确作品感"），确保 AI 输出符合教学理念
2. **动作提示词**：每个 AI 动作（生成框架、生成课次方案、修改方案等）的系统指令，控制 AI 的输出格式和行为
3. **项目信息**：用户填写的课程方向、年龄段、难度等

### 1.2 痛点

| 痛点 | 影响 | 频率 |
|------|------|------|
| 基线修改需改文件 + 重新部署 | 教研团队无法自主迭代课程设计理念 | 每周 1-2 次 |
| 提示词散落在代码中 | 调整 AI 行为必须开发介入 | 每周 2-3 次 |
| 基线是单一长文本，不区分年龄段/难度 | 8 岁和 15 岁的课程收到相同约束，AI 无法差异化生成 | 每次生成 |
| 表单字段全部自由输入 | 用户填写随意（如年龄段写"八九岁"），导致基线无法精准匹配 | 每次创建项目 |
| 全量基线注入浪费 token | 每次 AI 调用多消耗约 5000-6000 tokens | 每次调用 |

### 1.3 目标

让管理员能在 web 端自主管理课程设计基线和 AI 提示词，无需开发介入。同时通过结构化表单确保项目信息与基线精准匹配，提升 AI 生成质量并降低 token 成本。

## 4. 功能模块一：基线管理

### 4.1 概念说明

课程设计基线是指导 AI 生成课程内容的**规则集**。基线按维度拆分为独立文档，AI 调用时只注入与当前项目匹配的维度，而非全量。

### 4.2 维度结构

| 维度类型 | 维度值 | 数量 | 示例 |
|---------|--------|------|------|
| 通用基线 | general | 1 | 课程设计第一性原理、硬约束、禁止跑偏清单 |
| 年龄段基线 | A1、A2、A3、A4 | 4 | A2（8-9岁）：可承接清楚的单任务和 2-3 步简单结构 |
| 难度基线 | L1、L2、L3、L4 | 4 | L2（AI 基础应用）：AI 帮助理清思路 |
| 组织形态基线 | S1、S2 | 2 | S1（单课闭环型）：一节课 = 一个完整成果 |
| 产出物基线 | P1 ~ P11 | 11 | P3（故事类）：以故事为核心的创作类作品 |
| 分层规则矩阵 | matrix | 1 | 年龄段 × 难度 × 组织形态 × 产出物的组合规则 |

共 **23 条基线文档**。

### 4.3 拼装逻辑

当用户为一个项目（如 ageRange=A2, level=L2, orgForm=S1, deliverableType=P3）调用 AI 时，系统自动拼装：

```
注入 AI 的基线 = 通用基线 + A2 年龄段基线 + L2 难度基线 + S1 组织形态基线 + P3 产出物基线
```

而非注入全部 23 条。**节省约 60% 的基线 token 消耗。**

## 5. 功能模块二：提示词模板管理

### 5.1 概念说明

每个 AI 动作（如"生成课程框架"）有一个系统提示词模板，指导 AI 如何工作。模板中可使用 `{{变量名}}` 占位符，系统在调用时自动替换为实际值。

### 5.2 动作清单

| 动作 | 说明 | 典型场景 |
|------|------|---------|
| generate_framework | 生成课程框架 | 用户填写课程信息后，AI 生成框架结构 |
| revise_framework | 修订课程框架 | 用户对框架提出修改意见 |
| regenerate_lesson | 生成课次方案 | 为某一课次生成完整教学方案 |
| revise_lesson | 修改课次方案 | 用户对课次方案提出修改意见 |
| rewrite_field | 改写指定字段 | 用户点击某个板块要求重写 |
| rewrite_teaching_talk | 生成教学话术 | 生成教师课堂用语示例 |

### 5.3 模板变量

管理员在编辑模板时，右侧边栏展示可用变量，点击即可插入到光标位置。

**变量分组：**

| 分组 | 变量 | 说明 |
|------|------|------|
| 项目信息 | `{{项目标题}}` `{{课程方向}}` `{{目标年龄段}}` `{{目标级别}}` `{{课程组织形态}}` `{{产出物形态}}` `{{产出物名称}}` `{{预计课次数}}` `{{图片风格提示词}}` `{{大致框架}}` `{{核心诉求}}` `{{补充约束}}` | 从项目字段读取 |
| 标签信息 | `{{年龄段标签}}` `{{级别标签}}` `{{组织形态标签}}` `{{产出物标签}}` | 基线维度的显示名 |
| 基线内容 | `{{通用基线}}` `{{年龄段基线}}` `{{级别基线}}` `{{组织形态基线}}` `{{产出物基线}}` `{{分层规则矩阵}}` | 按项目属性自动匹配的基线文本 |
| 上下文 | `{{当前课次号}}` `{{当前课次标题}}` `{{全部课次概览}}` `{{当前课次方案}}` `{{修改意见}}` `{{目标板块}}` | 特定动作的运行时上下文 |

## 9. 向后兼容

| 场景 | 处理方式 |
|------|---------|
| 数据库无基线记录 | fallback 到文件读取（当前行为），零回退 |
| 数据库无 prompt 模板记录 | fallback 到代码中的硬编码默认值 |
| 旧项目 ageRange 为自由文本（如"8-12"） | 表单显示"自定义: 8-12"，允许重新选择标准选项 |
| 旧项目无 orgForm/imageStyle 字段 | 字段为 null，表单显示"请选择"，AI 调用时跳过对应基线 |
| 管理员改坏 prompt 导致 AI 输出异常 | 通过版本回滚恢复；系统有 JSON 解析失败自动重试机制 |

## 10. 非功能需求

| 项目 | 要求 |
|------|------|
| 性能 | 基线拼装查询 < 100ms（5 次 DB 查询，可加内存缓存） |
| 安全 | prompt 模板仅 admin 可编辑，API 有角色校验 |
| 可用性 | 变量侧边栏有分组和说明，降低使用门槛 |
| 数据安全 | 每次编辑自动保留版本，不可丢失历史 |
| 可维护性 | 新增变量仅需在变量注册表添加一条记录 |

## 11. 不在本期范围

| 功能 | 原因 |
|------|------|
| 图片 prompt 模板管理（独立于项目的图片风格系统） | 当前图片只有封面一张，投入产出比低 |
| prompt 测试/预览功能 | 用版本回滚 + 现有重试机制兜底 |
| 可扩展变量（管理员自定义变量） | 新增变量频率低（年 2-3 次），改代码成本可接受 |
| 基线维度间的组合禁用规则（如 A1+L4 禁用） | v2 暂不做 UI 校验，基线文本中已有文字说明 |
| 多语言 prompt | 当前仅中文用户 |
