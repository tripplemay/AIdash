# PRD｜AI Dash「课程研发」模块

> 版本：v1.0
> 日期：2026-03-16
> 状态：已确认
> 模块负责人：教学主管（rd_manager 角色）

---

## 1. 背景与目标

### 1.1 背景

AI Dash 教师授课系统当前的课程内容依赖外部制作（ChatGPT 生成 ZIP 包 → 管理员手动上传）。这个流程存在两个问题：

1. **效率低**：教学主管确定课程方向后，需要与 ChatGPT 反复沟通，手动下载 ZIP，再到管理后台上传
2. **质量难控**：课程框架和详细方案缺少系统化的迭代工具，修改意见靠口头或文档传递

### 1.2 目标

在 AI Dash 系统内新增「课程研发」模块，让教学主管可以：

1. **在系统内完成课程设计全流程**：从方向确认 → 框架生成 → 详细方案打磨 → 定稿 → 一键发布
2. **AI 辅助而非替代**：AI 负责初稿和局部修改，教学主管负责审阅和决策
3. **一键发布到课程库**：定稿后直接入库，老师端立即可见，无需手动下载上传

### 1.3 设计原则

- **页面少**：只保留 2 个核心工作页
- **信息不过载**：避免复杂审批后台、复杂状态中心
- **结果可控**：默认鼓励局部修改，不鼓励整套重生成
- **与现有系统一致**：接入现有 Sidebar / TopBar / 认证 / CSS 设计系统

## 2. 用户与权限

### 2.1 角色定义

| 角色 | 标识 | 说明 |
|------|------|------|
| 教师 | `teacher` | 使用课程包上课，不参与课程研发 |
| **教学主管** | **`rd_manager`** | **课程研发模块的核心使用者**，同时可管理课程包 |
| 管理员 | `admin` | 拥有全部权限 |

### 2.2 权限矩阵

| 功能 | teacher | rd_manager | admin |
|------|---------|------------|-------|
| 课程包列表 / 详情 / 课次 | ✅ | ✅ | ✅ |
| 课程研发模块 | ❌ | ✅ | ✅ |
| 管理后台 — 课程包管理 | ❌ | ✅ | ✅ |
| 管理后台 — 用户管理 | ❌ | ❌ | ✅ |
| 管理后台 — AI 模型设置 | ❌ | ❌ | ✅ |
| 管理后台 — 操作日志 | ❌ | 仅自己 | 全部 |

### 2.3 进入方式

- 系统 Sidebar 新增入口：**课程研发**（仅 rd_manager 和 admin 可见）
- 点击后默认进入**课程方向确认页**（新建项目）
- 页面右上角提供：「继续上次项目」「最近项目」

## 3. 核心工作流

```
教学主管填写课程信息
    ↓
【第一页】AI 生成课程框架
    ↓ 反复调整直到满意
确认框架
    ↓
【第二页】AI 生成逐节详细方案
    ↓ 逐节审阅、局部修改
确认定稿
    ↓
一键发布到课程库
    ↓
老师端立即可见
```

## 4. 页面 1：课程方向确认页

### 4.1 用户输入

| 字段 | 说明 | 必填 |
|------|------|------|
| 课程对象 | 目标学生群体描述 | ✅ |
| 课程方向 | 课程的主题/方向 | ✅ |
| 目标年龄段 | 如 8-12 岁 | ✅ |
| 目标级别 | 如 L1 / L2 / L3 | ✅ |
| 预计课次数 | 整数 | ✅ |
| 核心产出物 | 学生最终完成的作品 | ✅ |
| 大致框架 | 对课程结构的初步想法 | 选填 |
| 核心诉求 | 对课程设计的核心要求 | 选填 |
| 补充约束 | 其他限制条件 | 选填 |

支持**自动保存草稿**，避免输入丢失。

### 4.2 AI 输出

点击「生成课程框架」后，AI 返回：

- 整套课程一句话摘要
- 每节课标题
- 每节课简要概述
- 系列课程框架

### 4.3 用户操作

| 操作 | 说明 |
|------|------|
| **继续调整方向** | 输入修改意见，AI 按意见调整框架 |
| **优化标题** | 对某节课标题单独优化 |
| **优化概述** | 对某节课概述单独优化 |
| **确认进入详细方案工作台** | 锁定框架，进入第二页 |
| **暂停** | 保存当前状态，稍后继续 |
| **废弃** | 归档项目 |

### 4.4 版本管理

每次 AI 生成/调整框架都会创建新版本，可回溯查看历史版本。

## 5. 页面 2：课程详细方案工作台

### 5.1 AI 输出

基于第一页确认的框架，AI 生成**逐节详细方案**。每节课方案卡包含：

| 字段 | 说明 |
|------|------|
| 第几课 | 课次编号 |
| 课次标题 | |
| 本课一句话定位 | 简要定位描述 |
| 本课核心产出物 | 学生完成的作品 |
| 本课详细概述 | 完整的课程概述 |
| 本课主要任务 | 学生需要完成的任务列表 |
| AI 在本课中的作用 | AI 如何辅助教学 |
| 与前后课的衔接 | 课次之间的逻辑关系 |
| 授课表达示例 | 默认收起，展开查看教师参考话术 |

> **重要**：AI 生成的方案内容直接采用 v2 contentData 格式（hero + 7 sections + block 类型），确保定稿后可直接发布。

### 5.2 用户操作

| 操作 | 类型 | 说明 |
|------|------|------|
| 提出修改意见 | 输入 | 针对某节课输入修改意见 |
| 按意见修改本节 | 局部生成 | AI 根据意见修改该课次 |
| 重新生成本节 | 局部生成 | 完全重新生成该课次 |
| 单字段优化 | 局部生成 | 只修改某个字段（如标题、概述） |
| 重写授课表达示例 | 局部生成 | 重新生成教师参考话术 |
| 联动优化相邻课次 | 局部生成 | 修改一节课后自动调整相邻课次衔接 |
| 保存当前版本 | 保存 | 保存快照，可回溯 |
| 确认定稿 | 状态变更 | 锁定方案，进入发布流程 |
| 重新生成整套方案 | 谨慎操作 | **需二次确认**，覆盖所有课次 |

## 7. 定稿与发布

### 7.1 定稿流程

1. 教学主管确认所有课次方案满意
2. 点击「确认定稿」
3. 项目状态变为 `finalized`
4. 展示「一键发布」按钮

### 7.2 一键发布

1. 点击「一键发布」
2. 填写/确认课程包信息（slug、标题，部分字段自动填充）
3. 系统调用 `POST /api/admin/publish`
4. 将所有课次的 v2 contentData 直接写入 CoursePackage + Lesson
5. 状态自动设为 `published`
6. 创建发布记录（CourseRndPublishRecord）
7. 跳转到课程包详情页

### 7.3 重复发布

同一个项目可以多次发布：
- 发布到同一个 slug → 覆盖更新
- 发布到不同 slug → 创建新课程包

每次发布都会创建独立的 PublishRecord，支持追溯。

### 7.4 v2 规范合规

AI 在生成阶段直接输出 v2 规范的完整 contentData：
- `hero`（tags / title / subtitle / goal / outcome）
- 7 个固定 sections（core / ai_value / prep / flow / issues / materials / review）
- 8 种 block 类型（text / quote / list / template / box / grid / accordion / qa_pair）

Prompt 直接引用 `docs/product/content-integration-spec-v2.md` 规范文档。规范升级时只需更新文档，AI 输出自动同步。

## 8. AI 服务配置

### 8.1 服务提供商

OpenRouter 统一网关，1 个 API key 访问所有主流模型。

### 8.2 按动作配置模型

通过 `config/ai-models.json` 配置，教学主管可自由选择 OpenRouter 支持的任意模型：

| 动作 | 默认模型 | 原因 |
|------|---------|------|
| 生成框架 / 生成方案 | claude-sonnet | 需要高质量推理 |
| 局部修改 / 单字段改写 | gpt-4o-mini | 成本低、速度快 |

### 8.3 费用管理

- 费用以人民币显示
- 模型价格从 OpenRouter API 自动获取
- 汇率从 exchangerate-api 自动获取
- 管理员可在设置页手动编辑价格/汇率
- 三种更新方式：每日自动、手动刷新（覆盖全部）、手动编辑（不被自动覆盖）

## 11. 用户故事

### 教学主管 — 创建新课程

```
作为教学主管，
我想在系统内输入课程方向和要求，
让 AI 帮我生成课程框架，
这样我可以快速判断这个方向是否值得继续展开。
```

### 教学主管 — 打磨课程方案

```
作为教学主管，
我想逐节审阅 AI 生成的详细方案，
对不满意的部分提出修改意见让 AI 调整，
这样我可以高效打磨出高质量的课程方案。
```

### 教学主管 — 发布课程

```
作为教学主管，
我想在方案定稿后一键发布到课程库，
这样老师们可以立即在授课系统中看到新课程。
```

### 教学主管 — 查看 AI 费用

```
作为教学主管，
我想在工作台中看到当前项目的 AI 使用费用（人民币），
这样我可以了解每个课程的研发成本。
```

### 管理员 — 配置 AI 模型

```
作为管理员，
我想在设置页配置各动作使用的 AI 模型和价格，
这样我可以在质量和成本之间找到平衡。
```

### 管理员 — 查看操作日志

```
作为管理员，
我想查看所有用户的课程包操作记录，
这样我可以追溯谁在什么时候做了什么操作。
```
